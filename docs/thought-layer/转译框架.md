# 专业知识跨域转译 AI 框架

## 1. 系统定位

本系统用于将专业知识转换为其他领域人员或非专业人士能够理解、使用且不会产生关键误解的表达。它不是单纯的语言翻译器，而是一套集知识解析、语义守恒、认知转换、独立审核、有界返工、长期记忆、阶段总结和 Skill 演化于一体的多 Agent 系统。

系统分别处理三个不能互相替代的问题：

- 来源忠实性：译文是否准确保持源材料的含义。
- 外部真实性：源材料及译文中的重要主张是否有充分证据。
- 受众理解性：目标读者是否能够形成预期理解，且不会产生危险误解。

## 2. 总体角色

| 角色 | 性质 | 核心职责 | 禁止事项 |
|---|---|---|---|
| A 总体 | 固态控制面 | 记忆、编排、权限、决策、版本和 Skill 治理 | 不生成译文，不代替 C 审核 |
| B 转译 | 液态执行体 | 建立语义合同并完成知识转换 | 不决定自己的输出是否合格 |
| C 审核 | 液态执行体 | 独立审核、缺陷定位、证据核验 | 不直接重写最终译文 |
| D 阶段总结 | 周期治理体 | 比较候选、总结规律、提出改良 | 不直接修改线上 Skill |

B 和 C 是任务级无状态实例，完成任务后即可销毁。它们的长期历史、知识、日志和 Skill 均由 A 托管，并在运行时以最小必要范围注入。

## 3. A 的内部结构

A 是逻辑上的统一总体，工程上包含以下组件：

1. 控制器：推进状态，调度 B/C/D，保证同一任务中 B 与 C 阶段互斥，控制返工和停止。
2. 任务合同编译器：把需求编译成 B 的生成规范和 C 的审核规范。
3. 上下文管理器：维护当前上下文，并触发滚动蒸馏。
4. 记忆网关：统一控制当前上下文、即时调用库和总库的读写权限。
5. 蒸馏与结晶器：把原始历史转换为可调用、可回源的结构化结晶。
6. 检索与回源器：从结晶定位并展开原始材料。
7. 谱系与版本注册器：记录原始数据、结晶、合同、候选、审核、决定和 Skill 之间的派生关系。
8. Skill 注册表：管理 B/C Skill 的候选、有效、废弃和回滚版本。
9. 决策治理器：根据证据决定通过、返工、换策略、人工升级或终止。

A 拥有全部信息的治理权，但常规决策不得把全部历史加载到活动上下文中。

## 4. A 的三层记忆

| 层级 | 性质 | 主要内容 |
|---|---|---|
| L0 当前上下文 | 有限、临时、任务级 | 最近原文、旧内容结晶、任务状态、约束和未决事项 |
| L1 即时调用库 | 快速、可重建的工作视图 | 当前有效结晶、索引、活跃 Skill、必要原文片段和回源指针 |
| L2 总库/强库 | 完整、追加式、可审计档案 | 所有可观察原始记录、推理档案、结晶和历次版本 |

A 当前上下文由最近原文、相关结晶、当前任务状态以及总库回源指针组成。结晶只能替代 L0/L1 中的原文占位，绝不覆盖 L2 的原始数据。L1 必须能够由 L2 重建。

## 5. 总库的完整性边界

总库完整保存系统边界内可观察且依法允许保留的：

- A/B/C/D 的输入和输出；
- 显式自然语言推理说明；
- 检索结果、工具调用和执行状态；
- Prompt、模型、参数、合同、上下文包和 Skill 版本；
- 候选、审核、缺陷、返工和比较记录；
- 蒸馏前数据、蒸馏过程和所有结晶版本；
- A 的决定、人工介入、发布和回滚记录。

“完整推理档案”只指系统能够观察到的显式推理和执行轨迹，不声称取得模型未输出的隐藏内部计算。总库是完整历史库，不是真理库。

## 6. 推理档案

每个 Agent 在任务中产生以下显式记录：

- Observation：观察到的输入和证据；
- Hypothesis：采用的假设；
- Alternatives：考虑过的方案；
- Evidence：支持与反对证据；
- Decision：作出的判断；
- Uncertainty：未解决的不确定项；
- Action：实际输出或操作。

系统另外保存 ExecutionTrace，记录真实工具调用、权限、版本、状态变化和运行结果。外部事实、Agent 观察、显式推理、系统执行事实、C 的审核结论、A 的正式决定和 D 的改良提案必须分类保存。自然语言推理不得自动成为事实、结晶或 Skill。

## 7. 规范任务合同

每个任务只有一份由 A 托管的 `CanonicalTaskContract`，作为本轮任务唯一的语义和验收真源。它至少包含：

- 核心命题和因果链；
- 数字、单位、概率和量化范围；
- 前提、适用范围、例外和反例；
- 不确定性、争议和风险警告；
- 必须保留与允许省略的内容；
- 允许转换的范围与类比边界；
- 来源领域、目标领域和目标受众；
- 用途、风险等级和证据要求；
- `contract_id`、版本、哈希和来源谱系。

任务开始后合同不得原地修改。新增硬性要求必须创建新版本并重新编译任务。

## 8. B1/B2 与 C1/C2

B1/B2 和 C1/C2 是 B/C 内部的“固定预设层 + 任务扩展层”，不是四个长期 Agent。

- B1 生成预设：规定如何保持事实、因果、边界、不确定性和风险。
- B2 生成扩展：默认空置，用于受众细分、用途、篇幅、语气、格式、术语和额外禁用项。
- C1 审核预设：检查命题对应、遗漏、因果变化、数字错误、风险丢失和类比误导。
- C2 审核扩展：默认空置，用于法规、品牌、格式、引用、特定风险和抽检要求。

B1/C1 来自同一份规范合同的两个投影：

```text
CanonicalTaskContract
├── GenerationSpec → B1 + B2
└── ReviewSpec     → C1 + C2
```

## 9. 扩展槽与规则合并

B2/C2 必须结构化解析并经过权限、冲突和可满足性检查，不能作为无限权限的自由 Prompt。

规则优先级为：

```text
安全与法律
> 规范任务合同
> A 批准的领域政策
> B1/C1 基础预设
> B2/C2 任务扩展
> 风格偏好
```

扩展只能细化或收紧核心合同，不能削弱事实、因果、风险和安全底线。两个硬要求冲突时停止编译，由 A 裁决。

系统必须维护覆盖矩阵：

```text
合同条款 → B 生成指令 → C 审核项 → 所需证据
```

每项 B2 硬要求都必须映射为审核项；每项可能导致失败的 C2 内容要求必须在生成前进入 B 的规范。测试方法可以隐藏，验收条件不能隐藏。

## 10. 初次工作流

```text
输入进入 A 并写入总库
→ A 识别领域、受众、用途和风险
→ 实例化规范任务合同
→ 合并并校验 B1/B2、C1/C2
→ 冻结合同、模型、ContextPack 和 Skill 版本
→ B 生成译文、语义映射和推理档案
→ 原始结果写入总库并生成结晶
→ C 在独立上下文中首次盲审
→ 审核结果写入总库并生成审核结晶
→ A 决定通过、返工、人工复核或终止
```

高风险任务可增加合同预审：B 实例化合同，C 检查合同是否遗漏重要命题，A 冻结合同后 B 再正式生成。

## 11. 首次审核与信息隔离

C 首次审核只能读取原文、必要外部证据、规范合同、目标受众、匿名候选、C1/C2 量表以及 C 专用 Skill。C 不得读取 B 的推理、自辩、信心、旧草稿或候选身份。

C 输出结构化缺陷包：

```text
issue_id
判定与严重度
对应合同条款
原文和译文位置
判断证据
必须修复项
不得破坏项
审核置信度
是否需要人工专家
```

B/C 不建立自由对话通道。所有交接均经 A 校验、过滤和记录。

## 12. 驳回与三候选返工

审核不通过后，B 的三个隔离实例分别生成：

- Fresh-A：只看原始任务，完全重新生成；
- Fresh-B：同样不看旧稿和反馈，但使用不同策略、采样或模型配置；
- Repair：读取旧稿和由 A 编译的缺陷包，进行定向修复。

第二轮流程为：

```text
三个候选匿名并随机编号
→ C 分别在新上下文中完全盲审
→ C 另开上下文检查旧缺陷和新增回归
→ D 根据独立审核结果进行跨候选比较
→ A 决定采用、再返工、换策略、人工升级或终止
```

所有候选必须先通过绝对门槛，才能相对排序。

## 13. 结晶机制

结晶包括事实结晶、任务状态结晶、决策结晶、经验结晶、冲突结晶和 Skill 证据结晶。

生命周期为：

```text
RawEvent
→ 写入总库
→ Crystal draft
→ 来源对齐与完整性校验
→ validated
→ A 批准
→ active 并进入即时调用库
→ superseded 或 revoked
```

结晶必须保留来源、条件、例外、反例、不确定性、版本和回源指针。数字、单位、风险警告、严重缺陷、人工否决和未解决争议属于不可压缩项。新的重要结晶必须同时参考原始记录和旧结晶，不能持续执行“摘要的摘要”。

## 14. 强制回源

出现下列情况时，A 必须展开总库原文：

- 医疗、法律、金融、安全等高风险判断；
- 精确数字、引用、时间或措辞；
- 结晶冲突、过期、低置信度或缺少来源；
- C 提出事实、因果或条件异议；
- D 准备提出 Skill 更新；
- A 准备作出高影响决定；
- 来源被修订、撤回或可信度变化；
- 用户要求完整过程或原始证据。

## 15. A 蒸馏与 D 蒸馏

- A 的连续蒸馏用于压缩上下文、提高调用效率，不改变系统行为规则。
- D 的阶段蒸馏用于从多任务结果发现规律，并提出知识、流程、量表或 Skill 的变化。

D 在阶段边界、有效样本量达到阈值、严重错误聚集、模型变化或质量漂移时触发。D 只能读取已完成阶段的冻结快照，只有提案权，没有发布权。

## 16. Skill 演化

A 的 Skill 注册表是唯一真源。B/C 的 Skill 是由 A 分发的角色专用能力包。B Skill 与 C Skill 分别演化，只共享术语标准、合同协议和证据格式等中性资源。

生命周期为：

```text
D 提出候选
→ 数据筛选、去重和脱敏
→ 独立离线评测与历史回归
→ A 审批
→ 小范围试运行
→ 正式发布
→ 持续监控
→ 废弃或回滚
```

单次成功、单次审核意见或未经验证的推理不得直接进入正式 Skill。任务运行中不得静默升级合同、知识、模型或 Skill 版本。

## 17. 质量标准

一票否决项：

- 事实错误或虚构；
- 因果关系改变；
- 数字、单位或概率错误；
- 关键前提、例外、风险遗漏；
- 将不确定结论表达为确定事实；
- 无来源新增重要断言；
- 危险或误导性类比。

连续评分项包括信息完整度、术语一致性、目标受众可理解性、结构与教学顺序、类比边界、可追溯性和用途适配。

系统既要评测 B，也要评测 C 的漏检率、误拒率、证据质量、重复审核一致性和已知植入错误发现率。

## 18. 停止与人工升级

只有在全部硬门槛通过且各维度达到最低标准时，A 才能接受候选。

以下情况停止自动循环：

- 达到最大返工轮次、时间或成本；
- 连续两轮改善不足；
- 同类严重错误反复出现；
- B/C 对事实存在无法自动解决的分歧；
- C 的判断置信度不足或相互冲突；
- 来源本身含糊、冲突或证据不足；
- 候选趋同但仍不合格。

系统应返回“无法可靠完成”，而不是从不合格候选中强行选择。高风险任务按照风险等级进入人工复核。

```text

RawEvent
ReasoningReport

GenerationSpec
ReviewSpec
ContextPack
Artifact
```

每个对象记录任务、轮次、角色、父对象、合同哈希、上下文快照、模型、Skill、时间、权限、敏感等级和数据谱系。

## 20. 总原则

1. 原始数据永不被结晶覆盖。
2. 每个结晶必须能够返回原始证据。
3. 完整保存不等于事实正确。
4. A 拥有全部信息不等于每次加载全部信息。
5. B/C 共享验收合同，但不共享彼此的过程叙述。
6. B2/C2 可以扩展需求，但不能架空 B1/C1。
7. 审核方法可以隐藏，失败条件不能隐藏。
8. 相对最优不能替代绝对合格。
9. A 的信息蒸馏不能直接改变 Skill。
10. D 只能提出变更，A 只能依据评测证据批准变更。
11. 所有自动循环必须有停止条件。
12. 所有高影响决定必须可回源、可复现、可撤销。

最终形态是：A 作为拥有总库、即时库、上下文编译和治理能力的固态认知控制面；B/C 作为受同一合同约束、信息隔离、随任务生成和消解的液态执行体；D 作为跨阶段观察并提出演化方向的学习与治理层。
