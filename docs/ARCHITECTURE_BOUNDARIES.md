# 代码骨架、Agent 调整者与信息血肉

## 定义

- 代码骨架：认证、权限、订单和生产状态机、人工转交状态机、文件安全、数据库事务、审批、发布、回滚、审计、限流与外部接口契约。这些规则只能由开发者通过代码和测试修改。
- Agent 调整者：在确定的输入结构、字段白名单、风险门槛和审批流程内，生成候选内容、整理询盘、给出带不确定性标记的建议、发现问题并提出改良。Agent 不能直接改变骨架。
- 信息血肉：产品、图片、模型、页面、导航、FAQ、品牌事实、SEO/GEO 目标问题、值班说明和知识条目。它们可以通过 CMS 版本化、下架、发布和回滚。

## 硬性边界

1. Agent 只能生成候选版本，不能自行发布。管理员批准后，确定性服务再次校验版本、哈希、字段范围和中英文事实对。
2. 管理员可维护内容和运营规则，但不能跳过订单/生产流程、伪造外部 SEO/GEO 指标或读取其他客户的订单。
3. 开发者维护骨架参数、存储、排班和紧急控制；开发者仍是人类管理者，不是组织中的自动 Agent。
4. 订单商务流程和工厂生产流程固定顺序推进。Agent 只能整理资料或建议下一步，不能代替人类确认价格、付款、样品和生产完成。
5. 未获得企业数据、资质或连接器时写“待补充”，不能用模型推测或演示数据填充。
6. 访客只看到已发布内容和属于自己的订单；内部备注、员工身份、存储键、哈希、Agent 运行细节和审计信息不得公开。
7. 所有改变内容、规则、会话归属、订单状态和系统配置的动作进入审计记录。回滚形成新版本，不能偷偷覆盖历史。

## 已实现的内容与规则闭环

- CMS：管理员保存结构化草稿 -> Agent 候选 -> schema、双语事实、素材引用、字段范围与版本哈希校验 -> 管理员批准或驳回 -> 不可变发布版本 -> 访客只读已发布快照 -> 开发者回滚并产生新版本。
- SEO/GEO：管理员只维护市场、双语品牌事实、目标问题和技术输出开关 -> Agent 候选 -> 管理员批准或驳回 -> 版本与回滚。点击、排名、引用等外部指标只允许以后由已验证连接器写入。
- 客服规则：管理员只能修改白名单模式、规则开关和运营说明；投诉与法律硬门槛不可关闭。保存使用预期版本防止覆盖，并在下一次访客消息前从持久化状态刷新。规则变更立即生效并保留版本审计，不经过内容发布 Agent，以免产生“已批准但尚未生效”的安全歧义。
- 系统所有者保留直接发布恢复接口，普通管理员界面没有跳过 Agent 审批的路径。

## 数据流

```text
访客输入/管理员编辑/外部数据
        -> 结构化校验与权限检查
        -> Agent 生成候选或确定性业务状态变更
        -> 独立审核与风险门槛
        -> 人类批准（内容与高风险业务）；安全规则变更由管理员显式保存并立即审计生效
        -> 发布或事务提交
        -> 访客网站、客服、后台读取
        -> 审计、版本和可恢复备份
```

这个原则要求内容丰富时不改硬骨架，替换模型或数据库时不改业务状态机；只有确实需要新业务能力时，才通过代码、迁移和测试扩展骨架。
