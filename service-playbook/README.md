# 客服回复蒸馏手册

本目录用于沉淀经过脱敏的优秀客服回复结构，并为 AI 客服提供可执行的自主回复边界。目标不是机械复述问答，而是让 AI 像产品经理一样理解场景、推荐产品、解释取舍，并推动询盘进入下一步。

## 目录

- `patterns/reply-architecture.md`：产品经理式回复的七段结构。
- `patterns/product-discovery.md`：从客户需求到产品方案的需求发现流程。
- `permissions/autonomy-policy.json`：AI 可自主执行与必须人工确认的权限策略。
- `samples/2026-07-25-distilled-samples.jsonl`：脱敏后的结构化训练样例。

## 使用原则

1. 先复述客户目标，再给结论，不让客户重复解释。
2. 主动介绍与客户场景有关的产品、公司能力和工艺，不堆砌无关卖点。
3. 每次优先给一个主推荐，并说明推荐依据；必要时只补充一个备选及取舍。
4. 已批准知识库中的稳定信息可以直接回答；价格、交期、运费、税费等动态信息必须明确标记为待确认。
5. 一次只追问推进方案所必需的最少字段，并给出清晰的下一步。
6. 不编造事实，不把推测写成承诺，不替代人工完成受限决策。
7. 严格保留客户使用的数量单位；`套/件/副` 是采购数量，只有明确的 `数字 + 片` 才是拼图片数。

## 数据治理

只保存完成服务所需的最少信息。训练、评测和复盘材料必须去除客户用户名、姓名、手机号、地址、订单号及其他可识别信息；不得记录或复用即时成交价格。原始聊天记录与脱敏样例分离存储，并按岗位授权访问、设置保留期限和审计记录。客户要求删除或更正信息时，应按公司的数据处理流程执行。

## 推荐接入方式

系统按当前问题从 `samples/` 中选择最多一个脱敏范例，只学习回复结构，不把范例当作事实来源。检索层只提供已批准的产品与公司知识，决策层读取 `permissions/autonomy-policy.json` 判断是否可直接答复。回复生成后还要检查事实来源、单位、长度、待确认事项、追问数量和下一步；出现无依据的完成时长、年龄表现、金额或生产可行性时不得直接发送。
